# Accountability Alarm System

Claude plans the day through an MCP server. The iPhone turns the plan into full-screen AlarmKit alarms that break through Silent and Focus, then reports back check-ins, location and app usage. The whole thing costs £0.

See [SPEC.md](SPEC.md) for the design. **[docs/setup.md](docs/setup.md)** has the steps you do by hand.

```
claude.ai / Claude Code ──MCP──▶  Vercel (api/*)  ◀──REST──  iPhone app (SwiftUI + AlarmKit)
                                   │  Postgres (Neon)          ▲ Shortcuts automations
GitHub Actions ──every 10 min──▶ /api/tick                    │
GitHub Actions (macOS) ──builds──▶ Release "latest" .ipa ──SideStore──┘
```

## Layout

| Path | What |
|---|---|
| `api/*.ts` | Vercel Functions: thin wrappers around `src/routes.ts` |
| `src/routes.ts` | REST API: `GET /api/schedule`, `POST /api/events`, `GET /api/places`, `GET /api/status`, `POST /api/tick`, `GET /api/health` |
| `src/mcp.ts`, `src/tools.ts` | Stateless MCP server (Streamable HTTP, JSON responses) at `/mcp` |
| `src/rules.ts` | Rules engine: late for place, distraction during focus, no check-in → missed, play limit |
| `src/schedule.ts` | Alarm list with deterministic UUIDs, schedule version hash, and the week template that materialises 14 days ahead |
| `src/db.ts` | Schema (auto-migrates on first request) |
| `test/` | Vitest suite against in-process Postgres (PGlite) |
| `ios/` | SwiftUI app, generated by XcodeGen from `ios/project.yml` |
| `.github/workflows/` | `ios.yml` (unsigned .ipa → release), `tick.yml` (rules every 10 min), `backend.yml` (tests) |
| `docs/` | Setup, Shortcuts, Claude check-in prompts |

## How the phone stays in sync

`GET /api/schedule` returns the blocks and the alarms the phone should book. Each alarm has a **deterministic UUID**, a hash of block, offset, time and label.

The app diffs that set against `AlarmManager.shared.alarms`:
- It cancels alarms whose id isn't in the set.
- It books ids that are missing.
- Moving a block changes its alarm ids, so the old alarm is cancelled and the new one is booked.

Snoozes and test alarms are local-only. They're pinned so a sync doesn't cancel them.

Check-ins are written to an on-disk queue before any network call, with a `client_id` per event. The server ignores repeats, so retries are safe. The queue is flushed on every launch and sync.

## Development

```
npm install
npm test          # 39 tests, no database needed (PGlite)
npm run typecheck
npm run gen-token # make API_TOKEN / MCP_KEY values
```

Environment variables (Vercel): `DATABASE_URL` (set by the Neon integration), `API_TOKEN`, `MCP_KEY`. See `.env.example`.

The iOS app can only be built in GitHub Actions; there's no Mac. To change it, edit `ios/`, push, and read the Actions log.

## Security notes

- This is a public repo: no secrets and no personal data in code. Places and the timetable live only in the database.
- REST and Claude Code use `Authorization: Bearer <API_TOKEN>`.
- The claude.ai connector can't send headers, so it uses a separate `MCP_KEY` in the URL path (`/mcp/<MCP_KEY>`). Rotate it by changing the env var and updating the connector.
